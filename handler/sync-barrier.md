# 同步屏障与异步消息

> 系列：Framework-Source-Note · handler
> 难度：⭐⭐⭐⭐ 深入
> 更新：2026-08-20
> 前置知识：《Handler 消息机制》

---

## 一、一个被忽略的问题

上一篇我们讲：`MessageQueue` 按时间排序，`next()` 依次取出消息。但这里藏着一个矛盾：

> 如果队列里有一条**还没到时间的延迟消息**，而后面又来了**需要立刻执行的高优先级消息**，怎么办？

按普通逻辑，`next()` 会被延迟消息阻塞，高优先级消息只能干等。但 Android 的 **UI 渲染**恰恰是这种「高优先级、必须尽快执行」的消息。

**同步屏障（Sync Barrier）** 就是为解决这个问题设计的。

## 二、什么是同步屏障

同步屏障是一条**特殊的 Message**，它的特点：

- **没有 target**（`target == null`）
- 作用是：**挡住后面所有「同步消息」，只放行「异步消息」**

```
MessageQueue：
  [Barrier(target=null)]  ← 屏障，挡住同步消息
  [同步消息 A]            ✋ 被挡住
  [同步消息 B]            ✋ 被挡住
  [异步消息 C]            ✅ 放行
```

## 三、同步 vs 异步消息

| 类型 | 标志 | 说明 |
|------|------|------|
| 同步消息 | `isAsynchronous() == false` | 普通消息，默认类型 |
| 异步消息 | `isAsynchronous() == true` | 可穿越屏障 |

设置异步消息：

```java
Message msg = Message.obtain();
msg.setAsynchronous(true);  // 标记为异步消息
handler.sendMessage(msg);
```

> ⚠️ 注意：`setAsynchronous` 是**非公开 API**，普通开发者一般用不到。它是给**系统**（尤其是 UI 渲染）用的。

## 四、屏障如何插入和移除

屏障的操作也是隐藏 API，通过 `MessageQueue` 的方法完成：

```java
// 插入屏障，返回一个 token（用于后续移除）
int token = messageQueue.postSyncBarrier();

// 移除屏障
messageQueue.removeSyncBarrier(token);
```

**关键**：屏障插入后，`next()` 取消息时会：
1. 遇到屏障 → 跳过所有同步消息。
2. 优先取异步消息执行。
3. 直到屏障被移除，同步消息才恢复处理。

## 五、典型应用：UI 渲染（Vsync）

同步屏障最重要的应用，是 **View 的绘制刷新**。

Android 的渲染节奏由 **Vsync 信号**（屏幕刷新同步信号）驱动，每 16.6ms 一次（60Hz）。整个链路：

```
Vsync 信号到达
   │
   ▼
Choreographer（编舞者）发送「执行绘制」的异步消息
   │
   ▼
屏幕刷新前，先插入同步屏障
   │
   ▼
确保绘制消息（异步）能立刻执行，不被普通消息阻塞
   │
   ▼
绘制完成，移除屏障
```

**核心理解**：为了保证每帧都能按时渲染，系统在刷新前插入屏障，让「绘制」这条异步消息**插队执行**，普通业务消息（同步消息）暂时让路。

## 六、一个完整时序

```
时间线 ──────────────────────────────────→

MessageQueue：
[同步消息 A][同步消息 B][同步消息 C]...

Vsync 到来：
[Barrier][同步消息 A][同步消息 B]...
               ↑ 屏障插在队首

绘制消息（异步）到达：
[Barrier][异步消息-绘制]  ← 立刻取出执行
[同步消息 A][同步消息 B]  ← 继续被挡住

绘制完成，移除屏障：
[同步消息 A][同步消息 B]  ← 恢复正常处理
```

## 七、为什么普通开发者感知不到

同步屏障对开发者是**透明的**，因为：

1. 它由系统（`Choreographer`、`ViewRootImpl`）自动管理。
2. 普通消息都是同步的，屏障只是「短暂」让路给渲染，渲染完就移除。
3. 只有理解了这个机制，才能解释一些现象：**为什么某些耗时操作会导致掉帧**——因为它们（同步消息）阻塞了队列，渲染（异步消息）不得不等。

## 八、总结

| 要点 | 结论 |
|------|------|
| 同步屏障是什么 | target 为 null 的特殊 Message |
| 作用 | 挡住同步消息，只放行异步消息 |
| 异步消息 | isAsynchronous = true |
| 典型应用 | UI 渲染（Vsync 驱动的绘制） |
| 谁在用 | Choreographer / ViewRootImpl（系统） |
| 对开发者 | 透明，但解释了掉帧机制 |
